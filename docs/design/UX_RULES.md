# قواعد سلوك الواجهة

## 1. الشريط السفلي (Bottom Nav) — بنية معتمدة رسمياً

خمسة أزرار ثابتة، بنفس الترتيب عبر كل عالم يستهلكها — **مصدر الحقيقة `SALSABIL_CONSTITUTION.md
§25.1`**، لا يُكرَّر تفصيلها هنا:

```
الرئيسية | التواصل | الأقسام | محفظة | ملفي
```

هذه الدفعة غيّرت **الشكل البصري فقط** (عائم بدل كامل العرض، "الأقسام" مرفوعة ومميَّزة) — لا الأزرار
ولا ترتيبها ولا منطقها. راجع `docs/design/COMPONENTS.md` للتفصيل البصري.

## 2. زر بلا نطاق فعلي خلفه = "قريباً"، لا رابط معطوب

أي زر تنقّل يمثّل قدرة غير مبنية بعد (مثال: "التواصل"، "محفظة") يعرض تنبيهاً "قريباً" (Toast قصير
العمر، نفس نمط `WorldSwitcher.tsx`/`BottomNav.tsx` القائم) بدل الانتقال لصفحة فارغة أو رابط 404. لا
يُخفى الزر ولا يُعطَّل بصرياً — يحجز مكانه في البنية النهائية (مبدأ الخلايا الجذعية،
`SALSABIL_CONSTITUTION.md §4` بند 7).

## 3. الحركة: CSS Transitions فقط

لا مكتبة حركة خارجية (لا Framer Motion، لا أي بديل) في أي مكوّن جديد ضمن هذه الدفعة أو ما يليها من
عمل على نفس النطاق. كل انتقال/نبضة/تلاشٍ عبر خصائص CSS قياسية (`transition-transform`,
`transition-opacity`, `duration-*`) بتبديل className مشروط من حالة React — نفس نمط `CartCapsule.tsx`
(نبضة الإضافة) و`FeedTabBar.tsx` (تبديل التبويب النشط).

## 4. shadcn/ui كأساس، توكنز `--sb-*` كمصدر لون وحيد

أي مكوّن UI جديد يبني فوق `src/components/ui/*` (shadcn، `ADR-025`) حين يوجد بديل مناسب، بدل عناصر
HTML خام مُنسَّقة يدوياً من الصفر. الألوان دائماً عبر التوكنز الدلالية (`bg-primary`,
`text-muted-foreground`...) لا Hex مباشر — يعمل صحيحاً عبر أي `[data-world]`/`[data-personal-theme]`
بلا تعديل إضافي.

## 5. لا اختراع تفصيل غير موصوف

أي عنصر بصري لا يذكره موجّه المهمة صراحة، ولا يوجد له نظير في مرجع Lovable
(`D:\temp\reefam-lovable-reference`)، يُطلب توضيحه (`AskUserQuestion` أو ما يعادله) بدل افتراضه —
امتداد مباشر لـ`AGENTS.md §5` (Never Infer Missing Architecture) على طبقة التصميم تحديداً.
