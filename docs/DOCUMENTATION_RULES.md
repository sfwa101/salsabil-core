# قواعد نظام التوثيق — كيف تبقى وثائق سلسبيل حيّة ومتّسقة لسنوات

> هذا الملف هو "الدستور التشغيلي" لكل الوثائق الأخرى. أي تعارض حول *كيف* نوثّق (لا *ماذا* نوثّق) يُحسم من هنا.

---

## 1. التسلسل الهرمي لمصدر الحقيقة (Source of Truth Hierarchy)

```
CODE (Git Repository)
   ↓ مصدر الحقيقة الوحيد لِـ: ماذا يعمل فعلياً الآن

SALSABIL_CONSTITUTION.md
   ↓ أعلى مرجع لِـ: الرؤية، الرسالة، المبادئ العليا التي لا تُنتهك

docs/ (هذه الطبقة)
   ↓ مصدر الحقيقة لِـ: المعرفة الهندسية المنظَّمة (كيف تُبنى الأشياء)

specs/
   ↓ مصدر الحقيقة لِـ: نيّة الميزة قبل/أثناء التنفيذ

docs/DECISIONS.md
   ↓ مصدر الحقيقة لِـ: القرارات المعمارية ولماذا اتُّخذت

ideas/IDEAS.md
   ↓ مصدر الحقيقة لِـ: الأفكار غير المعتمدة بعد

Claude Project Knowledge
   ↓ طبقة سياق فقط — ليست بديلاً عن أي مما سبق، وقد تكون قديمة
```

**قاعدة صارمة:** إذا وجد Claude Code أو أي مهندس تعارضاً بين هذه الطبقات، **الطبقة الأعلى في هذا التسلسل تفوز، ويُسجَّل التعارض في `docs/DECISIONS.md` كـ `CONFLICT`** — لا يُحسم صامتاً.

## 2. نظام الحالات (Status Vocabulary) — لا كلمات أخرى

| الحالة | المعنى |
|---|---|
| `ACTIVE` | قرار/قاعدة نافذة الآن، معمول بها |
| `PROPOSED` | مقترح، لم يُعتمد بعد |
| `DEFERRED` | معتمد من حيث المبدأ، لكن تنفيذه مؤجَّل عمداً |
| `REJECTED` | نوقش وقُرِّر عدم اعتماده |
| `IMPLEMENTED` | موجود فعلياً في الكود، تم التحقق منه |
| `PARTIALLY_IMPLEMENTED` | جزء منه في الكود، جزء لم يُبنَ بعد |
| `SUPERSEDED` | كان معتمداً، استُبدل بقرار أحدث (لا يُحذف من السجل) |
| `OPEN_QUESTION` | غير محسوم، يحتاج قراراً بشرياً صريحاً |

## 3. مستوى الدليل (Evidence Level) — إلزامي لكل معلومة مهمة

كل معلومة جوهرية في أي وثيقة يجب أن تحمل وسماً من التالي، بجانبها مباشرة:

| المستوى | يعني أن المعلومة مصدرها |
|---|---|
| `CONSTITUTION` | منصوص عليها حرفياً في SALSABIL_CONSTITUTION.md |
| `DOCUMENTED_DECISION` | مسجّلة كـ ADR في docs/DECISIONS.md |
| `IMPLEMENTED` | موجودة في الكود فعلياً (Git هو الدليل) |
| `SPECIFIED` | موثّقة في ملف specs/ معتمد |
| `FOUNDER_DECISION` | قرار صريح من المؤسس في محادثة، خارج نص الدستور، بانتظار مزامنة |
| `PROPOSED` | اقتراح (مني أو من المؤسس) لم يُعتمد بعد |
| `INFERRED` | استنتاج من نمط في الكود/المحادثات، لم يُصرَّح به مباشرة |
| `UNKNOWN` | غير معروف، ولا يجوز تخمينه |

**قاعدة صارمة:** يُمنع تقديم `PROPOSED` أو `INFERRED` على أنه `ACTIVE` أو `CONSTITUTION` في أي وثيقة. إخفاء مستوى الدليل الحقيقي = انتهاك لهذه الوثيقة.

## 4. دورة حياة المعرفة (Knowledge Lifecycle)

```
IDEA → DISCUSSION → EVALUATION → ACCEPTED/REJECTED/DEFERRED
     → SPECIFICATION → DECISION/ADR → IMPLEMENTATION → TEST → DOCUMENTATION UPDATE
```

**لا يجوز القفز من IDEA مباشرة إلى CONSTITUTION.** كل فكرة تبدأ في `ideas/IDEAS.md`، ولا تنتقل لوثيقة رسمية إلا بقرار صريح من المؤسس.

## 5. متى تُحدَّث كل وثيقة، ومن يملك قرار التحديث

| الوثيقة | يُحدَّث عند | من يقرر |
|---|---|---|
| `SALSABIL_CONSTITUTION.md` | تغيّر رؤية/مبدأ كبير فقط | المؤسس فقط، عبر PROPOSED_CONSTITUTION_CHANGE |
| `docs/ARCHITECTURE.md` / `DOMAIN_MAP.md` / `DATABASE.md` | كل قرار معماري جديد أو تغيّر في البنية المنفَّذة | Claude يقترح، المؤسس يعتمد |
| `docs/BUSINESS_RULES.md` | كل قاعدة عمل جديدة يقرّرها المؤسس | المؤسس (قرار صريح) |
| `docs/DECISIONS.md` | كل قرار معماري/استراتيجي مهم، فور اتخاذه | Claude يسجّل، المؤسس يوافق على الحالة |
| `docs/CHANGELOG.md` | كل تغيير مهم (لا كل commit صغير) | Claude، تلقائياً مع كل مهمة كبيرة |
| `specs/*` | عند بدء ميزة جديدة كبيرة بما يكفي لتستحق Spec | Claude يكتب المسودة، المؤسس يعتمد قبل التنفيذ |
| `ideas/IDEAS.md` | أي فكرة جديدة تُطرح في محادثة | Claude يسجّل تلقائياً دون انتظار موافقة (التسجيل نفسه لا يحتاج إذناً، التطوير نعم) |

### 5.1 استثناء صريح على `PROPOSED_CONSTITUTION_CHANGE` — إضافة 2026-09-05، `BATCH1-GUARDIAN-REMEDIATION-001`

> يُغلِق فجوة إجرائية رصدتها مراجعة Guardian مستقلة على `CONSTITUTION-V2-BATCH1-GOVERNANCE-KERNEL`:
> تعديل مباشر على `SALSABIL_CONSTITUTION.md` نُفِّذ بتكليف مؤسس صريح داخل نفس المحادثة، بلا آلية
> `PROPOSED_CONSTITUTION_CHANGE.md` منفصلة قائمة فعلياً في المستودع — كانت الفجوة نفسها غير موثَّقة
> كاستثناء صريح، لا مجرد اتباعها ضمنياً.

**القاعدة:** تكليف المؤسس المباشر، الصريح، وغير المُلتبِس بتعديل `SALSABIL_CONSTITUTION.md` — داخل
محادثة موثَّقة (سجل الجلسة نفسه، أو Task Report يشير إليها) — **يُعامَل** كموافقة
`PROPOSED_CONSTITUTION_CHANGE` المطلوبة في جدول §5 أعلاه، **بشرط معاً**:

1. التكليف صريح ومباشر ("عدّل الدستور"، "أضف كذا للدستور"، وما في معناه) — لا استنتاجاً من طلب عام
   غامض يحتمل تفسيرات أخرى.
2. المُنفِّذ (Claude أو أي أداة أخرى) **يُوثِّق هذا الاستثناء داخل التعديل نفسه** — سطر/فقرة صريحة في
   `SALSABIL_CONSTITUTION.md` عند نقطة التعديل (أو في ملاحظة تنفيذية أعلى الملف) تذكر: أن التعديل جاء
   بتكليف مباشر، لا عبر `PROPOSED_CONSTITUTION_CHANGE.md` منفصل، ولماذا يُعتبَر ذلك كافياً.
3. لا يُستخدَم هذا الاستثناء لتبرير تعديل بادَر به الوكيل نفسه بلا تكليف صريح مسبق — يبقى ذلك مخالفاً
   لـ§5 وAGENTS.md §3 (Scope Lock) كما هو.

**مثال فعلي مطبَّق:** `SALSABIL_CONSTITUTION.md` v1.3 (2026-09-05) — راجع "ملاحظة تنفيذية على هذا
الإصدار" في أعلى ذلك الملف نفسه للتطبيق الحرفي لهذا الاستثناء.

## 6. قاعدة منع التكرار (Single Source of Truth per fact)

إذا كانت معلومة موجودة بالفعل في وثيقة أعلى في التسلسل الهرمي (§1)، **لا تُنسخ حرفياً** في وثيقة أخرى. استخدم إحالة:

```
«راجع SALSABIL_CONSTITUTION.md → §5 (Core + Domains)»
«راجع docs/ARCHITECTURE.md → قسم Adapters»
```

الاستثناء الوحيد: جملة تلخيصية قصيرة جداً (سطر واحد) لغرض القراءة السريعة، متبوعة بإحالة فورية للمصدر الكامل.

## 7. نظام منع التعارض الصامت

عند اكتشاف تعارض بين أي وثيقتين (أو بين وثيقة وكود):

1. **لا يُخفى التعارض، ولا يُحسم تلقائياً من Claude.**
2. يُسجَّل في `docs/DECISIONS.md` تحت قسم **CONFLICT LOG** بالصيغة:
   ```
   CONFLICT-00X
   بين: [الوثيقة أ] و[الوثيقة ب]
   الوصف: ...
   التأثير: ...
   يحتاج قراراً من: المؤسس
   الحالة: OPEN
   ```
3. يُخبَر المؤسس مباشرة في المحادثة.

## 9. قاعدة الحفاظ على الدستور مختصراً

`SALSABIL_CONSTITUTION.md` يحتوي **فقط**: الرؤية، الرسالة، المبادئ الحضارية، المبادئ المعمارية العليا غير القابلة للكسر، الهوية العامة، فلسفة الخلايا الجذعية، مبادئ الأمان والذكاء الاصطناعي وتجربة المستخدم على مستوى المبدأ (لا التفصيل)، والمبادئ التجارية الكبرى.

**كل تفصيل تنفيذي (كود، خوارزميات، جداول أسعار، أمثلة مفصّلة) ينتقل لـ `docs/` وليس للدستور.** إذا وُجد تفصيل من هذا النوع لا يزال في الدستور الحالي (v1.2)، يُسجَّل كملاحظة في `PROPOSED_CONSTITUTION_CHANGE.md` — لا يُنقل فعلياً إلا بموافقة صريحة.

## 10. قاعدة أخيرة: الوثائق جزء من النظام، لا ملاحق منفصلة

عند تنفيذ أي ميزة:
```
1. راجع الوثائق ذات الصلة (لا تخمّن)
2. نفّذ الكود
3. اختبر
4. حدّث الوثائق التي تغيّرت بسبب التنفيذ (خصوصاً DATABASE.md وARCHITECTURE.md وSpec الميزة)
5. سجّل قراراً معمارياً في DECISIONS.md إن وُجد
6. سجّل التغيير في CHANGELOG.md
```

وثيقة لم تُحدَّث بعد تنفيذ حقيقي = **دَين توثيقي (Documentation Debt)**، يُعامَل بجدية مثل الدَين التقني.
